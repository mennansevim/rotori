# Rotori Project Instructions

Before doing any project work, read the project documentation in this exact
order:

1. `docs/CLAUDE.md`
2. `docs/ARCHITECTURE.md`
3. `docs/CURRENT_TASK.md`
4. `docs/DECISIONS.md`

Do not assume context from previous conversations or sessions. Treat the
repository documentation as the source of truth.

If the documentation is outdated or conflicts with the current codebase,
update the documentation before implementing new features.
